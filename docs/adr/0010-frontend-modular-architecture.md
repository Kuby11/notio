# ADR 0010. Модульная архитектура фронтенда: shared, core, modules

- **Статус:** принято
- **Дата:** 2026-10-20

## Контекст

Фронтенд вырос из вертикальных фич `features/<feature>` со слоями domain → application →
adapters → ui (ADR 0009). Слои были распределены по папкам, но:

- публичный API фичи смешивал UI, use cases и адаптеры — границы держались на ревью;
- не было правила про состояние: Zustand-стор мог импортировать любой код;
- `shared/components` содержал компоненты каркаса, зависящие от фич, то есть «shared»
  знал о домене;
- API-репозитории импортировали `AccessToken` из фичи auth напрямую — модули
  зависели друг от друга, а не от интерфейса.

Нужна структура, где переиспользуемый код не знает о домене, модуль имеет фиксированную
анатомию с публичным `index.ts`, API не тянет состояние и UI, сторы приватны, у каждого
модуля есть facade-хук, а бизнес-логика живёт в хуках.

## Решение

### Каталоги

```
src/
├─ app/         # тонкие роуты Next.js
├─ core/        # composition root: container, providers, каркас (AppLayout/AppSidebar)
├─ shared/      # hooks, ui (примитивы), configs, types — без знания о домене
└─ modules/<module>/
   ├─ hooks/            # facade-хук модуля и хуки операций (один хук на файл)
   ├─ stores/           # Zustand: только UI-состояние модуля (если нужно)
   ├─ api/              # вызовы + Zod, кеш токена, без состояния и UI
   ├─ types/            # типы, порты, DTO-схемы
   ├─ utils/            # чистые функции, правила, мапперы, ключи Query
   ├─ ui/private|public # компоненты: внутренние и экспортируемые
   └─ index.ts          # публичный API модуля
```

Папки, которые модулю не нужны, не создаются: пустых `stores` или `ui`
с `.gitkeep` в репозитории нет.

### Правила границ

- `shared` не импортирует `modules`/`core`/`app`.
- Вход в модуль — только `modules/<module>` (index.ts): фабрика, facade-хук
  и публичные хуки, public-компоненты, публичные типы.
- `api` и `stores` используются только внутри своего модуля.
- `api` — только сеть и Zod: без React, TanStack Query, Zustand и `core`.
- Стор хранит сырое UI-состояние; снаружи доступен через facade-хук.
- У модуля есть facade-хук (`useAuth`, `usePages`, `useWorkspaces`, `useEditor`):
  он отдаёт компонентам запросы, мутации, стор и правила. Крупный facade можно
  разделить на хуки операций, но в одном файле — один хук, и имя файла совпадает
  с именем хука (`use-database-views.ts` → `useDatabaseViews`).
- Ключи TanStack Query — только в `utils/query-keys.ts` модуля.
- В `ui` живут только компоненты: папки `hooks` и `stores` внутри `ui` запрещены.
- Инверсия зависимостей: хуки зависят от порта (`types/ports.ts`), адаптер
  реализует порт в `api`, связывает их composition root. Отдельного слоя
  use case-классов нет: бизнес-логика живёт в хуках, доменные правила —
  в `utils`.
- `shared/types.TokenProvider` разрывает зависимость pages/editor/workspaces от модуля auth.

### Автоматическая проверка

`scripts/check-boundaries.mjs` запускается в составе `pnpm lint` и запрещает импорты
shared из modules, глубокие импорты модулей, вынос `stores`/`api` за пределы модуля,
React/Query/Zustand внутри `api`, папки `hooks/use-cases`, `hooks`/`stores` внутри `ui`,
отсутствие facade-хука, несколько хуков в одном файле и `query-keys.ts` вне `utils`.

### Composition root

`core/container.tsx` вызывает фабрики `createAuthModule`, `createPagesModule`,
`createWorkspacesModule`, `createEditorModule` и не знает про адаптеры и DTO. Модуль
сам собирает свой api-адаптер и отдаёт наружу только порт; токен приходит как
`TokenProvider` из `shared/types`.

## Альтернативы

- **eslint-plugin-boundaries или dependency-cruiser.** Отклонено: проект линтуется
  oxlint, отдельный ESLint-стек ради границ не нужен; скрипт на Node без зависимостей
  решает ту же задачу и переносим между ОС.
- **Оставить `features` и только переименовать папки.** Не решает приватность stores/api
  и не даёт facade-хукам единственной точки входа.
- **Экспортировать сторы из `index.ts`, чтобы «любой модуль мог прочитать состояние».**
  Отклонено: состояние перестаёт быть инкапсулированным, появляются скрытые связи.
- **Прокидывать use cases через провайдеры самих модулей.** Отклонено: DI протекает в UI
  и дублируется в каждом модуле.
- **Классы use case с одним методом `execute` под каждую операцию.** Отклонено:
  дублировали оркестрацию хуков и добавляли слой-прослойку без состояния; доменные
  правила перенесены в `utils`, DI остался в `useContainer()`.
- **Набор мелких хуков на каждую операцию.** Отклонено: компоненты собирали
  оркестрацию из нескольких хуков, а инвалидация кеша и правила расползались.
  Теперь модуль отдаёт один facade-хук с данными и операциями.

## Последствия

- ADR 0009 частично заменён: слои auth-фичи переехали (domain → `utils`, application →
  `hooks`, adapters → `api` + `types` + `utils`, ui → `ui/public`). Решения про
  сессию в TanStack Query, коды ошибок и `proxy.ts` остаются в силе.
- Покрытие меряется для чистой логики модулей (`utils`), порог 80%;
  хуки и UI проверяются компонентными тестами и smoke.
- Анатомия не требует пустых каталогов: папка появляется вместе с первым файлом,
  а фабрика модуля возвращает порт, а не набор use case-объектов.
- Компоненты работают с одним facade-хуком на модуль; ключи Query лежат в
  `utils/query-keys.ts` рядом с остальной чистой логикой.
- Новый домен добавляется модулем с фиксированной анатомией; общие примитивы и типы —
  только в `shared`.
- Каркас приложения (`AppLayout`, `AppSidebar`) переехал в `core/ui`, потому что собирает
  модули вместе; в `shared` его держать нельзя по правилу зависимостей.
