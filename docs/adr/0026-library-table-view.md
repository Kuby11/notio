# ADR 0026. Библиотека: таблица всех страниц вместо дерева на главной

- **Статус:** принято
- **Дата:** 2026-10-28

## Контекст

Главная рабочего пространства (`/workspaces/:id`) показывала то же дерево
страниц, что и сайдбар: дублирование навигации без единого способа увидеть
рабочее пространство целиком — кто автор, где лежит страница, когда её
правили. Задача — таблица в духе Notion Library: название, автор, источник,
время изменения и время последнего открытия, плюс вкладки-фильтры, поиск и
настройка столбцов.

Данные под это в API отсутствовали: `GET /pages` отдаёт один уровень дерева
(по `parentId`), а плоские списки были только у избранного, корзины и поиска.

## Решение

- **Новый плоский список `GET /pages/all?workspaceId=…`.** Отдаёт все
  неудалённые страницы workspace в порядке дерева, с `parentId` и
  `hasChildren` (флаг считается тем же запросом, что и в дереве).
  Альтернатива — обходить дерево по уровням — стоила бы запрос на каждую
  раскрытую ветку и не давала бы фильтровать по всему пространству.
- **Вложенность собирается на клиенте.** `usePages(…, 'all')` кладёт список
  в кеш `pageKeys.flat`, компонент строит карту «родитель → дети» и
  разворачивает строки; строка с детьми получает шеврон, отступ считается по
  глубине. Страница, чей родитель не найден, показывается как корневая.
- **Вкладки — реальные срезы данных.** «Недавние» — всё, «Избранное» —
  `isFavorite`, «Общие» — страницы других участников, «Личные» — мои.
  Вкладки Notion, которых в модели нет (AI Meeting Notes, Skills), не
  заводились: пустая вкладка хуже отсутствующей.
- **Фильтр, поиск и вкладки переводят таблицу в плоский режим** — строки
  сортируются по времени изменения. Индентация по скрытому родителю читалась
  бы как случайный отступ; «Недавние» без фильтров сохраняют порядок дерева.
- **Столбцы переключаются меню Display** (`core/ui/library`), набор
  столбцов — локальное состояние: это взгляд пользователя, а не данные.
- **«Открывалась» считается локально.** Сервер чтения не пишет:
  `LastPageTracker` вместе с последней страницей сохраняет метку времени в
  localStorage (`storePageVisit`, карта ограничена 300 записями), таблица
  читает её после монтирования — иначе SSR и клиент дали бы разные ячейки.
- **Компонент живёт в `core`**, а не в модуле `pages`: он собирает модули
  pages (строки), workspaces (имена авторов) и auth (кто такой «я»).
- **Время — `Intl.RelativeTimeFormat` со стилем `short`.** Утилита `shortAgo`
  отдаёт пару «единица + значение» (включая недели, месяцы, годы), локаль
  форматирует. `narrow` для русского отбрасывает «назад» и печатает
  «-3 дн.», поэтому взят `short`.

## Альтернативы

- **Оставить дерево и добавить столбцы в него.** Дерево отвечает на вопрос
  «где страница», библиотека — «что у меня есть»; в дереве нет места ни
  сортировке по времени, ни поиску по всему пространству.
- **Фильтровать на сервере.** Потребовало бы параметров под каждый срез и
  отдельного эндпоинта на вкладку; при объёмах личного workspace список
  приходит одним запросом и фильтруется мгновенно.
- **Хранить посещения на сервере.** Честнее между устройствами, но требует
  таблицы и записи на каждое открытие страницы; для колонки «когда я это
  видел» локальной метки достаточно, и она не создаёт нагрузки на API.

## Последствия

- Главная показывает всё пространство сразу: сортировка по времени, поиск,
  фильтры и переключение столбцов работают без сети.
- Список не постраничный (как избранное и корзина): на очень больших
  пространствах понадобится курсор — сигнатура `listAll` это позволит.
- «Открывалась» пуста до первого визита и не переносится между браузерами —
  это ожидаемое следствие локального хранения.
- Имена в колонке «Автор» берутся из списка участников; если он недоступен,
  показывается прочерк (свои страницы подписаны именем из сессии).
