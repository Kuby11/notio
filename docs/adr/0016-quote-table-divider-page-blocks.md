# ADR 0016. Цитата, таблица, разделитель и подстраницы

- **Статус:** принято
- **Дата:** 2026-10-23

## Контекст

Контракт уже описывал `quote` и `divider`, но вставить их из UI было нельзя:
slash-меню не содержало соответствующих команд. Типов `table` и `page` не
существовало вовсе. В Notion четвёртый базовый сценарий — подстраница:
страница внутри страницы, которая видна в документе как ссылка, открывается
по клику и появляется в дереве сайдбара.

Ограничения модели:

- `BlockContent` хранит плоский текст (без marks) — rich-текст запланирован
  на этап realtime;
- автосохранение диффает документ целиком: узел без маппинга в `BlockContent`
  молча удалился бы из базы, поэтому маппинг обязателен для каждого узла;
- `POST /pages` назначает id страницы на сервисе — клиент не может заранее
  знать `pageId` будущего блока.

## Решение

- **Цитата и разделитель — официальные узлы StarterKit** (`blockquote`,
  `horizontalRule`): маппинг в `utils/block.ts` уже существовал, добавлены
  только slash-команды и узлы для plus-меню. Markdown-триггер цитаты — `"`
  (пробел после кавычки): `>` занят toggle. Триггер `---` для разделителя
  приходит из StarterKit без дополнительного кода.
- **Таблица — официальное расширение `@tiptap/extension-table`** (Table,
  TableRow, TableHeader, TableCell; resizable выключен). В контракте —
  плоская модель `{ headerRow: boolean; rows: string[][] }`: ячейки —
  текст, первая строка из `tableHeader` считается заголовком. Таблица —
  одна строка `blocks`: строки и ячейки сериализуются в её content и
  не получают собственных `blockId`.
- **Подстраница — атомарный узел `subPage` и новый тип блока `page`**
  `{ pageId, title, icon }`. Дочерняя страница — обычная строка `pages`
  с `parentId` = страница-владелец блока; блок хранит денормализованные
  title/icon для отображения.
- **Оптимистичная вставка подстраницы** (`utils/sub-page.ts`): по команде
  `/page` узел вставляется сразу с пустым `pageId`, затем `POST /api/pages`
  создаёт страницу, и attrs узла обновляются на ответ сервиса. Узел без
  `pageId` не сериализуется в `BlockContent` — гонки с автосохранением нет.
  При сбое создания заглушка заменяется пустым абзацем и редактор сообщает
  об ошибке.
- **Мост React-слое в WeakMap**: расширения не знают про сеть и роутер —
  компонент `Editor` кладёт в `WeakMap` пару функций (создать страницу
  через мутацию facade-хука, открыть роут). `editor.storage` для этого
  не подходит: Tiptap типизирует его DOM-интерфейсом `Storage` без
  индексной сигнатуры.
- **Открытие по клику** обрабатывает контейнер редактора (router.push на
  `/workspaces/:workspaceId/:pageId`); с клавиатуры — Enter на выделенном
  узле. Ссылка без `href`: реальный маршрут зависит от workspace, которого
  узел не знает.

## Альтернативы

- **Хранить ячейки таблицы отдельными блоками.** Дало бы переиспользование
  автосохранения, но порядок ячеек и размерность таблицы пришлось бы
  восстанавливать по позициям, а вставка строки — синхронным пакетом
  запросов. Плоская модель в одной строке проще и атомарна.
- **Создавать страницу до вставки блока.** Проще поток, но блок появлялся
  бы с задержкой сети, а при медленном ответе команда выглядела бы
  «зависшей». Оптимистичная вставка даёт мгновенный отклик как в Notion.
- **ReactNodeViewRenderer для подстраницы.** Позволил бы Next `<Link>`
  внутри узла, но проект предпочитает официальные расширения без кастомных
  node view (см. ADR 0013); `renderHTML` + обработчик клика достаточно.

## Последствия

- `BLOCK_TYPES` вырос до 12 типов; реестр в `utils/block.ts` и схема
  контракта расширяются синхронно (компилятор требует новый `case`).
- Заголовок подстраницы денормализован: переименование дочерней страницы
  не обновляет блоки-ссылки до перезагрузки. Синхронизация появится вместе
  с realtime-событиями.
- Если пользователь удаляет заглушку, пока создаётся страница, страница
  остаётся в дереве пустой — как в Notion, где отменить создание нельзя.
- Таблицы пока без изменения ширины колонок и rich-текста в ячейках;
  это сознательные границы этапа, а не архитектурные ограничения.
