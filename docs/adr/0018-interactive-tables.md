# ADR 0018. Интерактивные таблицы: геометрия, управление и перестановка

- **Статус:** принято
- **Дата:** 2026-10-24

## Контекст

Таблица после ADR 0016 умела только вставку и редактирование текста. Из
Notion ожидается: перетаскивание границ колонок и строк, добавление
строк/колонок в существующую таблицу, видимый фокус ячейки и
перестановка строк/колонок целиком.

Ограничения:

- `prosemirror-tables` даёт `columnResizing` (колонки) и команды
  add/delete, но не умеет менять высоту строк и переставлять строки/
  колонки (в этой версии нет moveRow/moveColumn);
- при `resizable: true` таблицу рендерит внутренний TableView плагина
  columnResizing — он не применяет attrs узла, включая `data-block-id`;
- BlockContent таблицы хранил только текст ячеек — геометрия терялась
  при перезагрузке.

## Решение

- **Ширины колонок — официальный columnResizing** (`Table.configure({
  resizable: true })`): перетаскивание вертикальных границ, colgroup,
  атрибут `colwidth` у ячеек. Пустое место справа распределяет
  `lastColumnResizable`.
- **Высоты строк — свой плагин RowResize**: зона захвата — 4px у нижней
  границы строки; во время перетаскивания правится DOM напрямую, а на
  mouseup коммитится одна транзакция с attr `rowHeight` у `tableRow`
  (расширение TableRowBlock). Так история отмены остаётся одним шагом.
- **Геометрия сериализуется**: `TableBlockContent` получил опциональные
  `colWidths` (по колонкам, из `colwidth` ячеек первой строки) и
  `rowHeights` (по строкам); null — автоматический размер. Массивы
  пишутся только когда хотя бы одно значение задано.
- **Фокус ячейки — декорация**: плагин TableCellFocus через cellAround
  вешает класс `notio-active-cell` на ячейку с курсором; CSS рисует
  outline. Выделенный диапазон ячеек подсвечивает официальный
  `.selectedCell` (тоже с outline).
- **Управление — оверлей TableControls**: когда курсор в таблице, у
  заголовка колонки и слева от строки появляются пилюли: добавить
  (строку ниже/колонку справа), удалить (официальные deleteRow/
  deleteColumn) и ручка перетаскивания.
- **Перестановка — HTML5 drag с индикатором**: перетаскивание ручки
  пилюли показывает линию вставки (dragover считает индекс по половине
  ячейки под курсором), drop вызывает `moveTableRow`/`moveTableColumn`.
  Команды перестановки свои: таблица пересобирается одной транзакцией,
  attrs ячеек и строк переезжают вместе с ними.
- **data-block-id на таблице** восстанавливает плагин TableDomAttrs
  после каждого шага: он находит DOM таблицы (nodeDOM для таблицы с
  node view даёт обёртку tableWrapper) и копирует attr из узла.

## Альтернативы

- **Кастомный node view для таблицы** вместо синка attrs: больше
  контроля, но дублирует логику columnResizing и его colgroup.
- **Транзакция на каждый mousemove при ресайзе строк**: проще код, но
  история отмены и производительность хуже; DOM-правки + один коммит
  дают тот же результат дешевле.
- **Стрелки/меню вместо drag для перестановки**: дешевле в реализации,
  но пользователь явно просил перетаскивание.

## Последствия

- Минимальные ширина/высота — 20/24px: защита от «схлопывания» ячеек.
- Перетаскивание ручки строки/колонки работает внутри одной таблицы;
  перенос между таблицами не поддерживается.
- Геометрия — числа в пикселях; на других устройствах пропорции не
  пересчитываются (как в Notion с фиксированными таблицами).
- Оверлей позиционируется из DOM на каждый transaction/scroll — при
  скролле пилюли следуют за таблицей.
